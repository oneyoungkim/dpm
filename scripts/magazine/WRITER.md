# 매거진 글 한 편 내기 (예약 실행 순서)

하루 두 번 예약 작업이 이 문서를 그대로 따라 한다. 사람이 손으로 돌릴 때도 같다.
회차는 `morning`(아침, 오늘·이번 주 일정과 지금 뜨는 키워드)과 `evening`(저녁, 며칠 뒤에 읽어도 되는 글) 둘이다.

**발행 전용 폴더: `~/클로드/dpm-publish`.** 개발하는 `dpm` 폴더와 따로 둔 복제본이다. 개발 중인 변경과 섞이지 않게 하려는 것이고, 이 폴더에서는 발행 말고 아무 작업도 하지 않는다. 모든 명령은 이 폴더에서 돌린다. (순위 보조 수집 `scripts/trends/local-feed.sh`가 2시간마다 이 폴더의 코드를 읽어 쓰지만 파일은 건드리지 않는다.)

## 0. 준비

```bash
cd ~/클로드/dpm-publish     # 폴더가 없으면: gh repo clone oneyoungkim/dpm ~/클로드/dpm-publish
git status --short
git checkout main && git pull --rebase
npm ci --prefer-offline --no-audit --no-fund   # package-lock.json 이 그대로면 금방 끝난다
```

- `git status --short`에 뭔가 나오면 지난 실행이 중간에 끊긴 것이다. `git stash -u`로 치워 두고(지우지 않는다) 6번 기록에 적은 뒤 계속한다.
- 오늘 날짜로 시작하는 글이 `content/articles/`에 이미 있고 그 `publishedAt` 시각이 이번 회차(아침 = 12시 이전, 저녁 = 12시 이후)면, 이미 낸 것이니 끝낸다.

## 1. 글감 고르기

```bash
npm run magazine:pick -- --slot <morning|evening> --json
```

- 위에서부터 본다. 고르는 기준은 하나다: **1차 자료와 언론 보도로 근거 3개를 찾을 수 있는가.** 못 찾겠으면 다음 후보로 넘어간다.
- 키워드 순위에서 온 글감은 "주식", "AI"처럼 넓은 낱말이다. 그 낱말 뒤에 있는 **이번 주의 구체적인 사건**을 찾아야 글이 된다. `data/trends.json`의 대표 글 제목으로 무슨 일인지 짐작한 뒤, 그 일을 보도한 기사와 공식 발표를 찾는다. 한 사건이 키워드 여러 개에 걸쳐 있으면 한 글로 묶는다. 사건을 특정하지 못하면 그 키워드는 건너뛴다.
- 커뮤니티에서만 도는 이야기는 쓰지 않는다.
- 일정에서 온 글감은 실제로 그날 볼 것이 있는 일정만 쓴다(경기, 출시, 발표). "~까지 이용 가능", 협업 상품 판매 같은 항목은 건너뛴다.
- `evergreen.json`의 숫자는 확인되지 않은 실마리다. 그대로 옮기지 않고 전부 다시 확인한다.
- `content/EDITORIAL.md` 3장(쓰지 않는 것)에 걸리는 글감은 건너뛴다. 사람의 사생활 추문이 얽힌 사건은 회사·단체가 공식으로 밝힌 내용까지만 쓴다.

## 2. 조사

- 웹 검색과 페이지 읽기로 근거를 모은다. 순서는 주최 단체·제조사·통계 기관·공시가 먼저, 그다음이 통신사와 일간지다.
- 근거로 쓰지 않는 것: 커뮤니티 글, 나무위키, 블로그, 유튜브 댓글, 그리고 AI가 기사를 모아 다시 쓴 사이트(기사 끝에 "AI가 작성" 표시가 있는 곳).
- 최근 일은 기본 검색에 작년 기사가 먼저 나온다. 날짜를 검색어에 넣고, 그래도 안 나오면 검색을 `extended`로 돌린다.
- 본문에 쓸 숫자·날짜·이름·인용을 하나씩 적고, 옆에 그 사실이 실제로 적혀 있는 주소를 붙인다. 주소를 붙이지 못한 사실은 본문에 쓰지 않는다.
- **페이지 읽기 도구가 돌려주는 것은 요약이다.** 요약에 나온 숫자를 그대로 쓰지 말고, 쓸 숫자와 인용은 "이 숫자가 든 문장을 그대로 옮겨 달라"고 다시 물어 확인한다. 두 번 물어 숫자가 다르면 다른 매체로 한 번 더 확인하고, 그래도 다르면 쓰지 않는다.
- 통신사 원문이 안 열리면 같은 기사를 받아 실은 다른 매체에서 읽고, 근거 목록에는 실제로 읽은 주소를 적는다.
- 일정을 다루면 `data/events.json`의 날짜·시각과 주최 측 공지를 맞춰 본다. 다르면 공지를 따른다.

## 3. 쓰기

- `content/EDITORIAL.md`를 처음부터 끝까지 읽고 쓴다. 특히 5장(문장)과 6장(모양).
- 틀 만들기: `npm run magazine:new -- --title "제목" --slug 영문-slug --category 분류 [--kicker 꼬리표]`. 파일은 `content/articles/YYYY-MM-DD-<slug>.md`로 생기고 `publishedAt`은 지금 시각으로 들어간다. 머리말 형식은 `lib/articles.ts`의 `articleFrontmatterSchema`다.
- `publishedAt`은 지금 시각(한국 시간, `+09:00`)이어야 한다. 앞날 시각을 적으면 그때까지 사이트에 보이지 않는다. `draft` 줄은 넣지 않는다.
- 날짜는 "오늘", "어제" 대신 "11월 26일"처럼 쓴다.
- 본문은 2,500자 안팎을 목표로 한다. 2,000자를 겨우 넘기는 글은 한 대목이 빠진 경우가 많다.
- `sources`에는 본문에 실제로 쓴 근거만 넣는다. 읽기만 하고 안 쓴 자료는 넣지 않는다.
- `keywords`에는 이 글이 다룬 키워드 순위의 말을(상시 글감이면 그 글감의 id를), `eventIds`에는 다룬 일정의 id를 넣는다. 없으면 비운다.

## 4. 사진

```bash
npm run magazine:image -- "<영문 검색어>"
```

- 후보의 설명 페이지(`sourceUrl`)를 열어, 사진 속 대상이 글의 그 사람·그 물건이 맞는지 확인한다. 이름만 같은 다른 사람, 다른 연식의 차는 쓰지 않는다.
- 사진에 글과 상관없는 일반인이 크게 나오면 쓰지 않는다.
- 맞는 사진이 없으면 `image`를 통째로 뺀다. 표지는 사이트가 글자로 만든다. 다른 곳에서 사진을 가져오지 않는다.

## 5. 검사와 사실 대조

```bash
npm run magazine:check -- content/articles/<파일>.md
```

1. 오류가 0이 될 때까지 고친다. 고칠 때 뜻을 바꾸거나 근거 없는 말을 새로 넣지 않는다.
2. 검사는 분량·근거 개수·문장 규칙만 본다. 사실이 맞는지는 보지 못한다. 그래서 통과한 뒤, 본문의 숫자·날짜·이름·인용을 2번에서 적어 둔 주소와 하나씩 다시 맞춘다. 근거에 없는 문장은 지운다. 매체마다 숫자가 조금 다르면 어림수로 쓰거나("1조 9,000억 원 가까이") 출처를 밝혀 쓴다.
3. 처음부터 소리 내 읽듯이 읽고, 친구에게 설명할 때 하지 않을 문장을 고친다. 고쳤으면 검사를 다시 돌린다.
4. 세 번 고쳐도 검사를 통과하지 못하거나 사실 대조에서 근거가 빠지면, 그 글 파일을 `content/articles/` 밖으로 옮기고(초안 표시로 남기지 않는다) 이번 회차는 건너뛴다.

## 6. 발행과 기록

```bash
git add content/articles/<파일>.md docs/magazine-log.md
git commit -m "매거진: <제목>"
git push            # 거절되면 git pull --rebase 뒤 다시, 두 번까지
```

- 푸시하면 버셀이 다시 배포하고 몇 분 뒤 사이트에 뜬다.
- `docs/magazine-log.md` 맨 아래에 한 줄을 더한다: 날짜, 회차, 제목(또는 "건너뜀"), 글감이 어디서 왔는지, 건너뛰었다면 이유, 확신이 덜한 대목이 있으면 그것도.

## 하지 않는 것

- 글 파일과 `docs/magazine-log.md` 말고는 고치지 않는다. 검사 규칙(`scripts/magazine/rules.ts`), 편집 기준, 사이트 코드를 고쳐서 통과시키지 않는다.
- `git push --force`, 브랜치 지우기, 지난 글 지우기를 하지 않는다.
- 한 회차에 한 편만 낸다. 못 냈다고 다음 회차에 두 편을 내지 않는다.
- 바깥으로 나가는 요청에 사람 이름·이메일을 싣지 않는다.
